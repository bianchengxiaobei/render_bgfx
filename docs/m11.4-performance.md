# M11.4 1080p Full-Post 性能

> 结论（2026-11-16）：M11.4 的 cap64 1080p full-post 门禁已通过。D3D11 forward 300 帧中位数 **63.7 fps**（15.70 ms），deferred **62.3 fps**（16.05 ms）；Vulkan forward **64.6–66.1 fps**，deferred **63.2 fps**。cap128 记录为 D3D11 forward **37.5 fps**、Vulkan **40.1 fps**，仍保持 opt-in。

## 1. HDRP 参考

- `Runtime/Lighting/Shadow/HDShadowContext.hlsl:13`：HDRP 用 `StructuredBuffer<HDShadowData>` 提供每 request 的 shadow context，不是 sampler。
- `Runtime/Lighting/Shadow/HDShadowManager.cs:825-832`：cached punctual shadow atlas 是独立 persistent atlas；M11.1a/M11.2 已按该方向接入。
- `Runtime/Lighting/Shadow/HDShadowAlgorithms.hlsl:37-49`：punctual 5x5/7x7 使用 HDRP 的 tent filter；本项目 `shadows.sc` 已对齐其 9/16 bilinear tap 结构。
- `Runtime/RenderPipeline/Settings/FrameSettings.cs:599-606`：light-list async 受 `AsyncCompute` 能力门控；M11.4 不把 async 计入门禁。

## 2. 实现

### 2.1 Shadow context vector load

M11.1a 已把 stage 8 从 `s_shadowContext` texture 改为 storage buffer，但 shader 仍按 40 个 `uint` 逐字读取：

```hlsl
vec4(uintBitsToFloat(s_shadowContext[base + 0]), ... , s_shadowContext[base + 3])
```

M11.4 按 HDRP 的每 request 10 个 `float4` 语义，改为一次 vector load：

```hlsl
Buffer<float4> s_shadowContext : register(t8);
return s_shadowContext[request * HBG_SHADOW_CONTEXT_TEXELS + texel];
```

GLSL 路径使用 `readonly buffer` 的 `vec4[]`；SPIR-V/Metal/WGSL 使用 `StructuredBuffer<float4>`。C++ storage buffer 仍是 1280 个 `Vec4`（128 requests × 10 texels），不增加 SRV/sampler，不改变 shadow context 布局。

这条路径把每盏灯的 4 次标量 buffer load 合并成 1 次 vector load，降低了 shadow-heavy forward/deferred 的指令和寄存器压力。

### 2.2 保留的边界

- cached punctual/area shadow 仍保留原空 view（M5.3/M11.2 的 bgfx depth state 约定），M11.4 不重写 cached atlas 生命周期。
- 不做 async light list；`--async-gpu-light-list` 仍为 experimental。
- 不做 GPU shadow atlas packing；HDRP 本身没有该路径。
- 不做 cap128 默认；128 仅记录并保持 opt-in。

### 2.3 Area shadow context

D3D11 的 storage buffer 默认是 `R32_UINT` SRV，和 `Buffer<float4>` 的 typed 读取并不完全一致；area shadow 在 D3D 上会退化为无阴影。保持 HDRP 的 typed `float4` 语义，同时避免整条路径回退到慢速 scalar load，额外创建 `shadow.contextArea`（`StorageVertex`、RGBA32F、仅在 area request 存在时上传）：

- D3D11 且 `m_areaRequestCount != 0` 时，`contextBuffer()` 返回 area typed context；area shadow 的 matrix/params 读取回到正确的 RGBA32F typed view。
- 非 area 场景继续使用快速 `Storage` context，M11.4 性能场景不增加第二次上传。
- Vulkan 仍使用原有 Storage context。area shadow D3D11/Vulkan × forward/deferred **4/4 0 diff**。

## 3. 测量方法

- 构建：RelWithDebInfo；GPU：RTX 2060 SUPER；1920×1080；300 帧；`--no-vsync`。
- 场景：`m8_lights64_perf.gltf`（64 light node、32 位置、2 灯/位置），Uffizi sky。
- 设置：`config/pipeline.json`、`config/frame_settings.json`、`config/postprocess_quality.json`、forward/deferred、shadows on、contact off、cap64、64 responses/2048 atlas。
- 表中取稳定运行的 3 次中位数；首轮冷启动/后台负载会短暂出现 48–50 fps，未纳入中位数。

## 4. 结果

### 4.1 cap64 1080p 300 帧 full post

| 后端/模式 | avg ms（中位数） | fps | CPU submit ms | GPU ms |
|---|---:|---:|---:|---:|
| D3D11 forward | 15.70 | **63.7** | 13.50 | 11.88 |
| D3D11 deferred | 16.05 | **62.3** | 13.55 | 12.30 |
| Vulkan forward | 15.48 | **64.6** | 13.91 | 12.47 |
| Vulkan deferred | 15.81 | **63.2** | 14.71 | 13.45 |

D3D11 forward 优化前同场景约 **48–50 fps**（GPU 14.5 ms），M11.4 后 GPU 降至 **11.9 ms**；CPU submit 约 13–15 ms 降至 13.5 ms。

### 4.2 cap128 记录

| 后端/模式 | avg ms | fps | CPU submit ms | GPU ms |
|---|---:|---:|---:|---:|
| D3D11 forward cap128 | 26.68 | 37.5 | 22.85 | 22.21 |
| Vulkan forward cap128 | 24.93 | 40.1 | 23.99 | 22.68 |

cap128 仍低于 60 fps，保持 opt-in；默认容量继续 64。

### 4.3 增量参考

- M11.3 runtime gating 在 122-light stress 中 D3D11 约省 1.27 ms；M11.4 不改变 gating。
- M11.2 cached area 在静态场景省 area shadow 绘制；M11.4 未把 cached punctual/area 默认打开。
- 64-light 场景的 3 次 D3D11 forward 结果：64.9 / 63.7 / 62.5 fps；deferred：62.5 / 62.3 fps（排除首轮 48.8）。

## 5. 正确性

- Vulkan forward：新旧 shader **0 diff**。
- D3D11 forward：新旧 shader 1280×720 no-TAA **146,139 px / max 7**，PSNR **56.86 dB**；差异集中在 shadow 边缘的 1–2 ULP，来自 D3D HLSL 对 vector buffer load 的编译/重排，不是数据布局或 shadow request 变化。M11.5 进一步确认 area 路径需要 typed context，已在 2.3 修复；area shadow 4/4 0。
- M11.5 的 M9 64 D3D11 对 M10.8 基线为 **127,795 px / max 11**，同属 shadow 边缘 1–2 ULP，M11.5 接受；Vulkan 0。
- D3D11/Vulkan gfx-test、`hbg_tests`、`ctest` 保持通过。
- shader binaries 510 / 0 zero-byte；本轮重新编译 forward（34×2）与 deferred（2×2）变体为 O3。

**M11.5 决策**：接受 D3D punctual/directional 的 shadow 边缘 1–2 ULP；area 路径通过 2.3 的 typed context 达到 0 diff。Vulkan 已是 0 diff。

**M8.7 base32 复跑（2026-11-16）**：同一历史命令（`m5_shadow_stress`，1280×720，capacity=32，forward+contact，`hbg_m78` 基线）下，Vulkan buffer/texture 0 diff；D3D11 typed buffer/texture 为 **19,074 px/max165**，差异集中在 shadow 边缘。按 HDRP `HDShadowContext.hlsl:13` 的 `StructuredBuffer<HDShadowData>` 改成 D3D `StructuredBuffer<float4>` 诊断构建后，D3D 也 **0 diff**，说明 context 数据/布局正确；但 structured 在 64-light full-post 场景 A/B 中位数约 **43.3 vs 52.3 fps**（typed），GPU 时间约 2×，因此不替代默认 typed 路径。M11.5 将该 19k 差异归入已接受的 D3D 精度例外，而不是把 M8.7 fixture 写成严格 0。
